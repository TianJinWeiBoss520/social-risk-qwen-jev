# 项目叙述：如何在面试中准确表达

## 一句话

> 我做了一个中文图文内容风险发现研究项目，比较传统文本基线、Qwen3-VL垂域LoRA与Jev决策链路，并用分组防泄漏、冻结测试、召回/误报和成本评估来判断什么方案适合人工审核业务。

## 可讲的工作，不夸大个人角色

1. **定义任务与约束：** 选择图像+中文转录的标注数据，明确正类是厌女攻击，不把它泛化成所有风控场景。限制GPU成本、样本规模与云端发送字段。
2. **处理数据质量：** 固定来源commit、校验图像、检查重复及跨split候选，最终978/172/170分组划分，原始数据不改写；政治敏感性只有用户抽查，主动披露限制。
3. **先建立强基线：** Train-only TF-IDF，LR/XGBoost，多指标比较；发现文本特征很强，没有为了证明大模型价值跳过基线。
4. **做垂域微调：** 小rank语言注意力LoRA，一轮训练，视觉冻结，cosine与warmup；匹配prompt和加载路径做Base/LoRA对照。没有声称做过视觉联合LoRA或DPO。
5. **搭建可审计链路：** 图文感知输出严格JSON，移除模型标签与ID后将六字段证据假设交给Jev固定政策决策；控制授权范围、唯一调用账本、零重试、保守预算。
6. **评估业务取舍：** 冻结测试发现文本LR最好Macro-F1，大模型混合规则最好召回；Jev链路存在误报/漏报与开发落差，保留负面结果。
7. **工程整理：** 提取轻量接口，历史源码与哈希保留；补齐合成测试、数据卡/模型卡/评测卡、隐私保护和无计费默认CLI。不是已上线高并发系统。

## 三个有证据的关键数字

- 同一冻结test，Qwen Base→LoRA Macro-F1 76.65%→82.36%；这支持“小规模垂域微调对该基座该任务有效”，不是普遍优越。
- 文本C4 vs 文本ORLoRA：召回74.47%→91.49%，FN12→4，但FP0→12；适合解释漏报成本与人工复核成本。
- 固定政策的纯Jev vs 图文证据+Jev：开发 Macro-F1 69.42%→84.25%；后来在同一170条上的补充测试为63.04%→79.74%，FN35→15、FP2→12。支持证据处理的价值，但不是原始预注册对照，也没有隔离图像单因素；纯文本臂未独立优化政策。

最重要的限制：最终主方案文本OR图文Jev Macro-F1 87.25%，低于文本C4 90.36%；不能说“我提出的架构效果最高”。

## 常见追问

**为什么不用更大的模型？** 小数据与已有单卡资源下，先验证数据、基线和目标口径，模型变大不解决解释失真或标签口径问题。

**为什么只做语言LoRA也接收图片？** 视觉特征仍由冻结编码器提取，语言模块学习跨模态任务判定；冻结视觉不等于输入变为文本单模态。

**为什么不直接DPO？** 现有标签只监督分类，开发错误不天然产生事实正确的偏好解释。应先标注训练侧证据并排查政策差异；盲目偏好优化可能强化错误理由。

**Jev是否提高速度？** 下游决策组件约1秒，但完整链路还有约5秒的本地证据生成；不能忽略上游后声称比毫秒级LR更快。缓存级联只是历史模拟，非真实线上QPS。

**数据是否完全不涉及政治或隐私？** 只有抽查与基础脱敏，不能做完全保证；私有数据不公开，云端调用前明确发送范围与风险。

## 业务建议

低成本文本模型提供高精度快速信号；多模态模型用于发现文本看不出的风险和解释候选；Jev用于政策模块化探索。最终的模型选择取决于审核预算、漏报成本、误报容忍和新独立数据上的效果，不取决于架构名字是否更热门。
