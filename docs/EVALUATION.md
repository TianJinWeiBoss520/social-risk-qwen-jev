# 评测协议与结果解释

## 指标与排序

正类为源数据的Misogyny。主排序指标为Macro-F1（两类F1算术平均），同时展示accuracy、正类precision/recall和FP/FN。约72%的样本为负类，不能仅靠accuracy判断风险召回能力。

公开JSON只保存2×2聚合混淆矩阵，格式 `[[TN,FP],[FN,TP]]`。`social-risk results` 自动重算指标，README表格和单元测试核对同一份数据。聚合结果来自用户提供的已完成实验报告，不是本次重新跑模型，也不是官方验证认证。

## 冻结与防泄漏

TF-IDF只拟合Train，模型与分类阈值在Validation选择。最终170条测试的主方案是：`selected_text_label == 1 OR jev_probability >= 0.40`。固定文本模型为C4，文本阈值0.70，Jev固定控制阈值0.50。

测试只在配置冻结后揭示；看到测试表现后不调参数，不把其错例用于训练。Validation已反复用于开发，包括23条私人诊断，不能再宣称独立留出。进一步优化需要新、未参与设计的外部评测集。

## 三种不能混淆的对照

1. Qwen base vs LoRA：必须相同prompt、模态和精度加载路径。短标签训练验证与七字段证据验证不同。
2. 多模态＋Jev vs 纯Jev：纯Jev仅输入转录，多模态臂多了Qwen证据。固定政策且不上传Qwen label。此实验没有隔离“图像”单因素，也不是同时刻API调用。
3. 主方案 vs 文本基线：OR通常提升召回，也可能增加误报。最终测试主方案Macro-F1 87.25%不及文本C4的90.36%；差值组bootstrap95%区间[-9.68,+2.80]个百分点，不能声称全面超越。

原报告 `JEV_T040`、`JEV_T050_FIXED_CONTROL` 实际是图文Qwen证据＋Jev，不是纯Jev。后来补做的纯 Jev 170 条对照已完成，主表新增 t=0.40 与固定控制 t=0.50 两行，使用同一组纯文本分数；不能将它们说成原始预注册方法。

补充测试没有改动模型、政策或阈值。相同 t=0.40 时，纯 Jev 与图文证据＋Jev 的 Macro-F1 为 63.04% 与 79.74%；FN 35→15，FP 2→12。该对照移除整个 Qwen 证据包；固定政策仍提及纯文本臂缺少的 `perception_hypotheses`，不能视为优化过的最佳纯文本基线。仅有聚合矩阵时不推导逐条配对显著性。来源与续跑审计见 [补充测试说明](PURE_JEV_TEST_SUPPLEMENT.md)。

## 非法输出与未完成任务

非法JSON需记录失败并复核，不把失败伪造为安全。历史短标签脚本将未解决输出作为错误记录；完整比较需要检查coverage。不存在的K-Means、视觉LoRA、DPO成绩不补零、不编造。

## 时延、成本与概率

CPU batch1计时只含TF-IDF变换和分类，不含启动/文件/网络。Qwen计时包含处理与生成，不含加载；云端往返和感知相加只是历史重建，不能等同线上QPS或端到端P95。

三段是操作展示 `[0,.2) / [.2,.8) / [.8,1]`，不是监督严重度标签；本项目没有证明分数校准。原三个项目API批次的已知token费用估计约0.014654美元；新增纯 Jev 测试的成功请求约0.00425519美元，总计约0.01890878美元。非完整账户账单，不含GPU/税费/未知失败请求。软件预测预算不等于服务商硬限制。
